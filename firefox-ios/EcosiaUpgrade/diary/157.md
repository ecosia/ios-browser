# Firefox 157 upgrade diary

This diary records the upgrade of Ecosia's iOS browser from Firefox 147 to Firefox 157 (Jira epic MOB-5026): what each ticket did, what it decided and why, and every trap worth checking next time. Engineers and agents write to it in the same format (see [README.md](README.md)), so QA findings can be traced back to the decision that caused them. The plan is in [milestones.md](../../../.scratch/firefox-upgrade/milestones.md); the branching approach is [ADR 0007](../../../adr/0007-graft-firefox-upgrades-onto-main-via-upgrade-branch.md).

## 155.1 checkpoint

The upgrade starts from the 155.1 experiment, which moved Ecosia from Firefox 147.2 to 155.1 on `origin/firefox-upgrade-155.1`. Its 20 tickets are copied unchanged into [155.1-experiment/](155.1-experiment/); this section summarises them.

### What the experiment did

- **Characterization tests first (ticket 01).** Before resolving anything, `FirefoxUpgradeCharacterizationTests` captured the highest-risk Ecosia behaviours as tests against pre-upgrade code: default search engine identity (non-Google), the invisible-tab/auth session flow, NTP impact counter, and the start-at-home override.
- **Inventory before resolution (ticket 02).** All Ecosia commits since the verified fork point (`firefox-v147.2`) were squashed into one commit (`c5afa25d3b`) and rebased onto `firefox-v155.1` in a single in-progress rebase. An intent-diff manifest and a symbol-dependency report were generated up front to guide every later ticket.
- **Area-by-area resolution (tickets 03 to 18).** Project manifest, Redux `ModernAction` migration, Nova theming, Remote Settings v2, feature flag configuration, Quick Answers `Info.plist`, shared test mocks, core hot files (tab management), then verticals: toolbar/address bar, main menu, homepage, bookmarks, settings, tracking protection, launch/onboarding, and a final telemetry and bootstrap sweep. Ticket 00 collected conflicts no ticket owned.
- **Integrate and verify (ticket 19).** It inherited 404 still-unresolved conflicts, finished the merge, and fixed the defects only the compiler found. Result: the `Ecosia` scheme builds and `EcosiaTests` runs **947 tests, 7 skipped, 0 failures**, including the characterization tests. The simulator comparison against pre-upgrade screenshots (ticket 19 AC 6 and 7) stayed open because no baselines existed and `git-lfs` was missing. The final upgrade is the single commit `c162a7c953`, whose parent is the tag `firefox-v155.1`.

### Product decisions now in force

From [milestones.md](../../../.scratch/firefox-upgrade/milestones.md#product-decisions):

| Firefox feature | Decision |
| --- | --- |
| Translations | Keep |
| Page summaries | Keep, on-device only. Hidden entirely on devices that cannot summarize on-device |
| AI controls settings hub | Keep, showing only translations and summaries |
| Google Lens | Out |
| Quick Answers (voice) | Out |
| VPN promotion | Out |
| Ad blocker | Out for now: its block list hides the ads on Ecosia's own search results, which fund tree planting |
| "Nova" visual redesign | Off |

Two of these differ from what the experiment shipped: the experiment kept the ad blocker as a functional setting (experiment ticket 07) and kept Quick Answers' `Info.plist` usage strings (experiment ticket 08). M1 ticket 08 turns both off.

### Traps

Every trap, gotcha and lesson recorded in the experiment's tickets, one bullet each, with its source ticket. The tickets also refer to an earlier numbered trap list ("trap 2", "trap 4d", …) from a working handover note that was never committed. Where a bullet matches one of those numbers, it says so, and it is described only by what the tickets say about it. Trap 1 is never referenced and is unknown. Ticket 19 also numbers its own "additions to the trap list" 1 to 8, and its addition 6 is **not** the handover's trap 6.

**Merge results that look clean but are not**

- **Defects outside conflict markers** (handover trap 2). An auto-merged class header took Ecosia's form while the conflict region held upstream's body (12); upstream deleted an enum case Ecosia uses in a clean, unconflicted file (13); an Ecosia-owned type stopped conforming because upstream's protocol gained a member (17); upstream's new `GleanWrapper` methods auto-merged with live bodies (18); a new upstream call site used an Ecosia-changed signature (19 §9b). Sources: 12, 13, 17, 18, 19.
- **Two independent deletions of different paths for the same symbol remove it with no conflict.** Upstream and Ecosia each deleted one of the two `MockThemeManager` files, so the class vanished from `ClientTests`. Found only by `swiftc -parse` over the Tuist source list; the intent-diff manifest did not catch it. Source: 09.
- **A purely Ecosia-created file can disappear with no signal.** `MultiplyImpact.swift` (583 lines, user-facing) was matched as a rename of an upstream-deleted file and deleted. Run the `comm`-based set difference from ticket 19 §9h once per upgrade: files Ecosia created on top of the fork point that are missing from the result. Source: 19 (§9h, addition 1).
- **New upstream files arrive with no conflict and no Ecosia delta, so nothing flags them** (handover trap 3b). A new upstream mock conforms to a protocol Ecosia extended (12); a new upstream test contradicts an Ecosia substitution outright (18); new live Glean call sites auto-merged un-silenced (18). Sources: 12, 18.
- **When Ecosia's strategy is "silence or replace everything", every upstream addition is a hole in it.** `GleanWrapper` (18); four WidgetKit files calling theme accessors Ecosia comments out (19 §9c). Source: 18, 19 (addition 3).
- **When Ecosia changes a signature, every new upstream call site is a silent break.** `formatAndTruncateURLTextField` gained a third caller; `ToolbarElement.init` gained a parameter ahead of Ecosia's. Neither conflicts; only type checking finds them. Source: 19 (§9b, addition 2).
- **Upstream removed or reshaped an API that Ecosia code still uses** (handover trap 4, "upstream deleted the symbol"). `SimpleToast` (vendored), `PhotonActionSheet.UX.bigSpacing`, the `WallpaperState` memberwise init, `ReaderPanel` `applyTheme`, `isMinimalAddressBarEnabled`. Source: 19 (§6, §9d, §9f, §9g, §9i).
- **An Ecosia comment block can swallow new upstream methods.** In `BookmarksViewController`, upstream inserted three methods right where an `/* Ecosia: */` block opened, so they landed inside the comment while their call sites stayed live (same shape as ticket 11's `LocationTextField.applyTheme`). A plain `grep` sees the declaration; build comment-aware scanning once (nested `/* */`, string literals). Source: 19 (§9e, addition 8).
- **Relocated upstream code silently drops the customization next to it** ("the classic relocation trap"). Upstream moved a constraint into an `#available(iOS 26)` branch in `TopTabsViewController`; Ecosia's customization had to be re-homed onto the `else` branch. Source: 19 (§6).

**Reading Ecosia's side correctly**

- **Upstream already does what Ecosia's change did** (handover trap 4). Ecosia's `animated:` parameter versus upstream's new `animatingDifferences:` (13); a `/* Ecosia: */` block documenting `nonisolated(unsafe)`, which upstream now does itself (16, "textbook trap 4"); wallpaper telemetry tests upstream rewrote without Glean (13). Take upstream; the file can become byte-identical. Sources: 13, 16.
- **An Ecosia workaround whose reason expired** (handover trap 5). `SearchLoader`'s Swift 6 workaround (19), `ActionTokenPair` in `AppDelegate` (18), the MOB-4384 `WindowManager` workaround (18), a Tuist source exclusion for a file upstream deleted (12), wallpaper tests disabled to avoid Glean (13). Sources: 12, 13, 18, 19.
- **Taking upstream's file wholesale can drop a delta Ecosia needs, even with no markers** (handover trap 4d). `NimbusOnboardingTestingConfigUtility.swift` lost its `@testable import Client`. Before taking upstream, check `git diff <fork-point> <ecosia-head> -- <file>` for real Ecosia content. Sources: 16, 19 (§11a).
- **Ecosia's side of a test file is often an older Firefox, not a customization.** Its fork-point delta reads as a reverse upstream diff. Resolving "in favour of HEAD" reinstates dead APIs (seven Microsurvey and mock files). Check the delta for Ecosia content; if there is none, take upstream. Source: 19 (§12, addition 6). This is the "trap 6" step 4f of the M0 plan refers to.
- **A flagged symbol is often just a name** (handover trap 4c2). The symbol-dependency report's method-name hits (`append`, `animate`, `isFeatureEnabled`) and type hits in comments are false positives. Source: 19 (AC 8).
- **Upstream renames make Ecosia's delta look empty or new** (handover trap 7, "rename bullet"). `ModernLaunchScreenViewControllerTests` became `OnboardingLaunchScreenViewControllerTests` (delta read as 0 lines); `TermsOfServiceManager.swift` moved to `Client/` (delta read as a new file); `TabsPanelStateTests` moved into `TabTray/Redux/`; `CertificatesHandler.swift` became `CertificatesFetcher.swift` but kept the class (near-miss). Sources: 16, 17, 19.

**Build system and targets**

- **Targets Ecosia does not build: take upstream** (handover trap 6). `XCUITests`, `Tests/UITests`, `L10nSnapshotTests`, `SyncIntegrationTests`, `ExperimentIntegrationTests` and the `.xctestplan` files are not Tuist targets here. Confirm with `grep -rn XCUITests firefox-ios/Tuist firefox-ios/Project.swift`. Sources: 11, 13, 14, 15, 16, 18, 19.
- **Build-system defects are invisible to every source-level check.** 155.1 added `Client/Assets/reader-mode/` with files byte-identical to existing ones; Ecosia's Tuist glob picked up both, giving five `Multiple commands produce …` errors. Any upstream directory addition under a globbed path is a candidate. Source: 19 (§9a, addition 4).
- **Where upstream compiles a file matters as much as what is in it.** Upstream lists sources in `Client.xcodeproj`, Ecosia globs. Diff both ways: files upstream compiles into a different target (§11a) and files it compiles into no target, which may not even build (§11b). Source: 19 (§11, addition 5).
- **`tuist generate` succeeds with missing module dependencies** (handover trap 3, "import check"). A missing Swift module only fails at compile time, so diff every module imported under `firefox-ios/Client/` against the target's declared dependencies. A newly added file also needs `tuist generate` re-run before the build sees it. Sources: 03, 10, 19 (§9f).
- **A green app build is not a green test build.** Thirteen more compile errors over eight iterations lived only in the test targets. Source: 19 (§11 to §14, addition 7).

**Assets**

- **Git's rename detection pairs unrelated assets.** A blanket "keep theirs" put Ecosia's `shareMedium` `Contents.json` into upstream's `syncLarge.imageset`. Re-hash every resolved asset against both sides; a match with neither is a rename artifact. Source: 19 (§4).
- **Orphaned imagesets.** Restoring only the `.pdf` of an imageset Ecosia deleted with its `Contents.json`, or leaving an orphan PDF after upstream deleted the imageset, breaks the asset compiler. Source: 19 (§4).

**Process**

- **Stage explicit paths during a conflicted rebase.** Never `git add` a directory or `git add -A`. Repair with `git update-index --index-info`; `git checkout -m` rewrites marker labels and refuses add/delete conflicts. Source: 18.

Other warnings in the tickets, not labelled as traps there:

- While `.swiftlint.yml` was conflicted, SwiftLint silently fell back to its default configuration, so lint runs from that time were unconfigured. Source: 00.
- Ecosia's targets define no `TESTING` condition, so upstream's `#if TESTING` bodies in `StoreTestUtilityHelper` would compile away; the fork's copy has no `#if`. Source: 19 (§14).
