# Change inventory: Firefox 155.1 to 159.1

What Firefox changed between `firefox-v155.1` (`04df3bd66b`, this branch's [`UPSTREAM_BASE`](../README.md#upstream_base)) and the upgrade target `firefox-v159.1` (`f48a79cffc`), and what each change means for Ecosia. Written for MOB-5041 (upgrade ticket 15) on 2026-11-13. It guides MOB-5042 (apply the upgrade), MOB-5043 (lock the feature configuration) and MOB-5044 (QA test plan).

- **Target:** `firefox-v159.1`, fixed by Dario on 2026-11-11. It was the latest Firefox release then. Later releases wait for the next upgrade.
- **Sources:** the 443 commits between the two tags (`git log firefox-v155.1..firefox-v159.1`), the diff of `firefox-ios/nimbus-features/*.yaml`, `nimbus.fml.yaml`, `FeatureFlagID.swift` and `NimbusFeatureFlagLayer.swift`, and a dry merge of `HEAD` (`d34ecfe1e7`) with the target.
- **Marks:** **keep** (take upstream's change), **out** (Ecosia turns it off or doesn't show it), **needs product decision** (open question for product, listed at the end). Fixed decisions from M1 are in the [diary](../diary/157.md#product-decisions-now-in-force).

## Architectural changes

- **Toolbar actions leave Redux state** (FXIOS-16630, 16930, 16627; 156.0 to 159.1). Leading, trailing, navigation and browser actions moved from `AddressBarState` to `AddressToolbarContainerLens`, and two more actions became `ToolbarModernAction`. This is where Ecosia's toolbar customization lives: `AddressBarState.swift` is the most-changed conflicting Swift file (11 commits, 746 lines), with `AddressToolbarContainerModel.swift`, `LocationView.swift` and `AddressToolbarContainer.swift` near the top of the ranking.
- **Redux modern action migration continues** (FXIOS-16769): `TabPanelViewActionType.addNewTab` and its middleware.
- **Build configurations:** `Fennec` renamed to `Debug`, and `Fennec_Testing` folded into it (FXIOS-16780, 15086). Ecosia builds with Tuist and its own configurations, so only `bin/nimbus-fml-configuration.sh` is affected: it conflicts, and upstream's new `Debug` case duplicates Ecosia's (both map to `developer`).
- **Search engines:** `ASSearchEngineProvider` decoupled from `Profile` (FXIOS-11799), early search config v3 support (FXIOS-17096). Both touch Ecosia's search engine changes: `ASSearchEngineProvider.swift` conflicts, `ASSearchEngineSelector.swift` merges silently.
- **Tabs:** group IDs on tabs (FXIOS-16994), skipped session reads for live web views (FXIOS-17014), `TabModel.hash` hang fix. `TabManagerImplementation.swift` conflicts.
- **Swift 6:** isolated deinits adopted and reverted in 156.1; more `nonisolated(unsafe)` removed. Xcode version checks replaced by a Swift version macro (FXIOS-17194). iOS 27 and Xcode 27.1 fixes.
- **SwiftLint:** new rules `balanced_xctest_lifecycle`, `comma_inheritance`, `collection_alignment`, a lower `function_body_length` threshold, `.git` excluded. `.swiftlint.yml` conflicts, and the new rules also apply to Ecosia's own files.
- **Dependencies:** Lottie removed; Kingfisher 8.12 to 8.14; Glean 70.1.0; swift-syntax 603.0.2 for macro prebuilts; application-services nightlies, including a Places breaking change (a-s #7468). `Package.resolved` conflicts are Ecosia's deletions (Tuist resolves packages).
- **Theming:** Nova private-theme override infrastructure; content dark mode no longer affects the UI theme (FXIOS-16856).
- **Reader mode:** embedded New York fonts removed for the system serif (FXIOS-16975).
- **Tests:** shared Redux store setup (`StoreTestUtility`, which conflicts), `makeProfile()` everywhere, `FeatureFlagTestUtility`, `FxAPushMessageTest` deleted (Ecosia modified it: modify/delete conflict).
- **Dead code removed:** Objective-C FxA search paths, the orphaned FxA and `ecec` directories, four unreferenced files including `TabViewState.swift` (an Ecosia Tuist exclusion becomes dead), the old `AdsClientDocumentsDirectoryMigration`, search telemetry investigation code.

## Questions for product

These need an answer before MOB-5042 applies the upgrade.

1. **Address bar swipe gesture.** Since 158.0, swiping up on the address bar opens the tab tray interactively, and dragging a tab to the top of the screen closes it. Beta and developer already had it; 159.1 turns it on for release users too. Keep it, or turn it off for Ecosia?
2. **Search term in the address bar.** 159.1 can show the search term instead of the URL while the page is the default search engine's results page, for example the query on an Ecosia results page. Upstream ships it off. Do we want it on?
3. **App Store install attribution.** Firefox's SKAdNetwork conversion values (install, first ad click, set as default, URL loads) already ship in production unchanged, with Mozilla's mapping. 159.0 and 159.1 change the mapping again. Does Ecosia's marketing use these postbacks, and should we keep Mozilla's mapping, use our own, or turn it off?
